# Orbital Authority

Космический экономический симулятор на MonoGame. N-body гравитационная физика (Sun–Earth–Moon) в реальных единицах СИ, процедурная 3D-визуализация, орбитальная камера.

Проект в активной разработке: физика, ECS-ядро и базовый рендер уже работают на реальных данных, экономический/геймплейный слой (ресурсы, фракции, колонии, ИИ) существует только как каркас классов без реализации — см. [Статус модулей](#статус-модулей).

## Стек

- .NET 10, C# (`Nullable`, `ImplicitUsings` включены)
- MonoGame.Framework.Native 3.8.5.1 (десктоп, Vulkan-бэкенд по умолчанию)
- Microsoft.Extensions.DependencyInjection — сборка графа зависимостей в `Program.cs`

## Сборка и запуск

```bash
dotnet build OrbitalAuthority.slnx
dotnet run --project src/OrbitalAuthority.Client
```

## Управление

| Действие | Клавиша / ввод |
|---|---|
| Пауза симуляции | `Space` |
| Ускорить время | `]` или `PageUp` |
| Замедлить время | `[` или `PageDown` |
| Сбросить скорость до 1.0x | `Backspace` |
| Следующий объект в списке | `Tab` |
| Отменить следование / выбор | `Esc` |
| Вращение камеры вокруг цели | средняя кнопка мыши (drag) |
| Зум | колесо мыши |
| Панорамирование цели камеры | `WASD` / стрелки |
| Центр камеры в (0,0,0) | `Home` |
| Открыть/закрыть список объектов | клик по заголовку `[+] Object: ...` |
| Выбрать объект и переместить камеру к нему | клик по имени в списке |

Ручное панорамирование (`WASD`/`Home`) отменяет слежение за объектом; вращение камеры и зум — нет, ими можно продолжать разглядывать выбранный объект.

Шкала скорости времени: `0.01x … 100x` (`SimulationClockController.SpeedSteps`).

## Архитектура

Модули — отдельные проекты в `src/`, зависимости направлены сверху вниз:

```
Core ← ECS ← Physics ← Rendering ← Client
      ↖ Gameplay ↗
```

| Проект | Назначение |
|---|---|
| `OrbitalAuthority.Core` | Общие утилиты: время, логирование, сериализация, события (каркас) |
| `OrbitalAuthority.ECS` | `World` — массивы компонентов по `EntityId` (без архетипов, просто `T?[]`) |
| `OrbitalAuthority.Data` | Константы (`PhysicsConstants`) и загрузчики определений (каркас) |
| `OrbitalAuthority.Physics` | Гравитация, интеграторы, `PhysicsPipeline` |
| `OrbitalAuthority.Gameplay` | Фабрики сущностей (`SolarSystemFactory`), таймер симуляции |
| `OrbitalAuthority.Rendering` | Камера, процедурная генерация сфер, HUD |
| `OrbitalAuthority.Client` | MonoGame `Game`, DI-композиция, игровой цикл |

`OrbitalAuthority.AI` и `OrbitalAuthority.Tests` лежат в `src/`, но **не подключены** к `OrbitalAuthority.slnx` и ни к чему не референсятся — заготовки на будущее.

### Игровой цикл (`OrbitalAuthorityGame`)

`Update`: ввод (клавиатура/мышь) → таймер симуляции → выбор объекта (Tab/клик/дропдаун) → камера → `N` тиков `PhysicsPipeline.Tick(dt)` (число тиков ограничено `PhysicsConstants.MaxTicksPerFrame`, чтобы высокий `TimeScale` не подвешивал кадр) → жёсткая привязка камеры к выбранному объекту (без сглаживания — иначе на высоком `TimeScale` камера отстаёт от объекта).

`Draw`: подсчёт FPS по реальным вызовам `Draw` за секунду → очистка цвета и буфера глубины → 3D-сцена (`CelestialBodyRenderer3D`) → 2D HUD поверх (`SpriteBatch`).

## Физика

- Единицы — СИ (метры, секунды, килограммы); `PhysicsConstants.G = 6.67430e-11`.
- Гравитация: прямое попарное суммирование (`NewtonianGravityField`), N² — годится для десятков тел, не для тысяч.
- Интегратор: **Velocity Verlet** (`VelocityVerletIntegrator`, зарегистрирован в `Program.cs` как `IIntegrator`). `SymplecticEulerIntegrator` оставлен как альтернативная реализация того же интерфейса.
- `PhysicsPipeline.Tick(dt)` считает ускорение дважды за тик (до и после обновления позиций) и явно переносит его в `Ax/Ay/Az` через `ComputeAccelerations()` — оба интегратора читают уже готовое ускорение, а не считают его сами.
- Число под-тиков на кадр подбирается так, чтобы шаг одного тика не превышал `PhysicsConstants.MaxStableDt` (1 час), с жёстким потолком `MaxTicksPerFrame = 500`.
- `World` — простые массивы фиксированного размера (`EcsConstants.MaxEntities = 1024`) без переиспользования освободившихся `EntityId`.

## Рендеринг

- Камера — орбитальная, `Camera3D`: вращается вокруг точки `Target`, вычисляет `View`/`Projection` в системе координат, привязанной к позиции камеры (**camera-relative rendering**). Это важно: масштаб системы (~10¹¹ м) не влезает в точность `float`, поэтому мировые координаты хранятся в `double` и приводятся к `float` только после вычитания позиции камеры — тогда GPU оперирует небольшими числами независимо от того, где во Вселенной находится сцена.
- near/far плоскости масштабируются от текущей `Distance`, иначе фиксированная пара не работает на диапазоне зума от сотен км до триллионов метров.
- Тела рисуются одной и той же процедурной UV-сферой (`SphereMeshGenerator`, единичный радиус), масштабируемой под `MassComponent.Radius` — **реальный физический радиус**, без художественного преувеличения. На масштабе всей системы планеты — несколько пикселей, как и в реальности.
- Освещение — `BasicEffect.EnableDefaultLighting()` (простой direct-light, три встроенных источника). Солнце — исключение: рисуется без освещения, `EmissiveColor` вместо `DiffuseColor` (звезда не может быть наполовину в тени от направленного света).
- HUD (`SpriteBatch`, поверх 3D-сцены): таймер/скорость/FPS-панель и выпадающий список объектов с наведением, кликом и авто-закрытием.
- Шрифт (`Content/DefaultFont.spritefont`, JetBrains Mono) включает только ASCII 32–126 — весь текст, который реально выводится на экран (HUD, список объектов), должен оставаться на английском/ASCII, иначе MonoGame упадёт на отсутствующем глифе.

## Статус модулей

**Работает и физически осмысленно:**
`World` (ECS) → `SolarSystemFactory` (Sun/Earth/Moon) → `PhysicsPipeline` (гравитация + Verlet) → `CelestialBodyRenderer3D` + `Camera3D` → HUD/список объектов.

**Только каркас (`// TODO: реализация`, пустые классы):**
- `Gameplay`: колонии, население, фракции, дипломатия, ресурсы, пилоны, корабли, мегаструктуры
- `Physics`: коллизии (`Broad/NarrowPhase`), пространственные индексы (`Quadtree`, `Octree`, `BarnesHutTree`, `SpatialHash2D`)
- `Core`: `SimulationWorld`, `SystemScheduler`, `EventBus`, `SaveManager`
- `AI`: вся стратегия/поведения (проект не подключён к solution)
- `Tests`: тестовый проект-заготовка (не подключён к solution)

Экономический геймплей (то, ради чего затевался симулятор) на данный момент не реализован — есть только физическая подложка.

## Известные ограничения

- HUD-подсказка `[R] reset` не соответствует коду: сброс скорости к 1.0x — это `Backspace`, а не `R`.
- Гравитация считается N² без пространственного индекса — не масштабируется за пределы текущих трёх тел без доработки (`BarnesHutTree`/`Octree` уже есть как заготовки).
- `World.Destroy()` не переиспользует освободившиеся `EntityId` и не уплотняет массивы.
